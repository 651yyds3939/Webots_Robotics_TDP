新 Navigation.py 保持完整行走周期，近球时面向预计球路、通过身体坐标侧移/后退调整脚位，射门前站稳，角色位置设滞回。TeamPolicy 用共享触球证据暂保持球者，CLEAR 朝前。使用**相同时间/种子**的导航版本复测：连续走路片段中位数 1.36 秒，恢复尝试 16 次，球轨迹 14.757 m，36 次触球归属转换；仍 0:0，且没有实际射门，整体对抗性能仍未达到要求。这轮 navigation-match-* 保留的是近距离射门策略修改之前的版本，源码散列在 manifest 中。

随后单人连续进攻用真实 RedForwardA 控制器、其他球员旁站。初始球 x=1.2 m，旧 x>1.8 m 射门规则在 180 秒内只推到 x=3.546 m，**未进球并明确失败**，记录为 attack-before-finishing-change.*。射门夹具只有约 0.4 m 推进能力，因此改为朝球门开口最近可用点带球，距离目标小于 0.5 m 再射门。

最终 attack-result.json / attack-webots.log / attack-final.png 显示在 147.16 秒完成整球入门，球末位置约 [4.578, -0.781, 0.070]，只有 RedForwardA 触球。测试没有对手干扰、没有比赛重启/计分流程，不代表实战成功率；速度仍然低。完整未删节的原始轨迹保存在发布目录外的私有备份中。

最终 33 个逻辑检查通过；skills-* 是最终策略的近距射门、带球位移、接球者触球回归，均通过。最后射门时机修改后尚未重复整场四对四，不能用早期配对比赛代替最终战术验收。下一步需要更快且经过稳定性标定的步态、连续攻击的多场景成功率、随后小规模和完整对抗评估。
