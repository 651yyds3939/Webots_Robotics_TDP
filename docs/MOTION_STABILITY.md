# 中途跌倒的诊断记录（2026-10-13）

当前球员以预录 `.motion` 关节目标执行移动，尚未实现躯干平衡与脚底支撑反馈控制。已有比赛决策、朝向反馈、动作限位和起身触发，并不等于步态及动作衔接已经验证稳定。

## 日志确认的现象

固定单人进攻基线 `runs/dribble_baseline_01` 在以下仿真时刻记录：

| 时刻 | 动作或观测 |
|---|---|
| 47.04 s | 开始直行 |
| 48.04 s | 开始右侧移 |
| 49.60 s | 开始左侧移 |
| 49.72 s | 触发 `recover_back`；躯干参考点高度约 0.252 m |
| 49.92 s | `standing=false`，高度约 0.151 m |
| 51.24 s | 高度约 0.059 m，仍未站起 |
| 53.12 s | 再次尝试 `recover_back` |
| 56.52 s | 恢复普通转向命令 |

两次连续起身尝试不能解释为两次独立跌倒。高度和朝向观测确认发生物理失稳，不只是起身计数变化。侧移反向与失稳时间接近，但现有日志不足以证明反向切换是唯一原因。

## 代码与动作适配问题

- `SoccerController.act()` 的行走保护条件为当前动作启动后不足 0.96 秒。`ForwardLoop.motion` 的周期为 0.960 秒；代码没有对后续循环计算播放相位，也没有确认支撑脚状态后再切换。这是首段最短行走时长保护，不能表述为每个循环的安全切换保证。
- IMU 的 yaw 用于导航，roll/pitch 超过 0.8 rad 时触发起身。当前没有根据倾角误差调整髋/踝动作的全身平衡环，也没有脚底接触/压力反馈来确认支撑状态。
- 侧移、转向和踢球通常等待动作结束，但动作结束不等于身体速度、重心和支撑状态已经稳定。检查右侧移结束与左侧移开始的原始腿部目标角后，差值为零；因此不能直接将该次跌倒归因于两份动作的腿部目标角突跳。
- 起身选择只按 pitch 正负区分前后，侧向倾倒也进入这一分支；未分类侧倒姿态或等待稳定着地。原始第一次起身在身体仍处于下落过程中启动，需要进一步验证这一时机。
- 首次 `recover_back` 的运行日志记录 108 个限位裁剪样本。静态动作/模型对照同样得到 108 个超限值，其中涉及膝、踝和髋关节；裁剪改变了原预录轨迹，起身兼容性仍需标定。该计数不表示 108 个关节，也不能单独证明裁剪是起身失败的唯一原因。

NAOqi 1.12 的[厂商步行控制文档归档](https://www.cs.cmu.edu/~cga/nao/doc/reference-documentation/naoqi/motion/control-walk.html)说明了关节反馈稳定和在双支撑状态停止步行的设计，可作为运动控制参考；当前 Webots 程序没有调用该步行引擎。

## 下一轮需要的测量

先记录动作切换及失稳前后的 IMU roll/pitch、实际动作播放相位、目标/实测关节角与脚底接触状态，再在无球隔离场景中重复“直行→侧移”“右侧移→左侧移”“转向→直行”。新增诊断记录本身不改变控制策略。

对照结果应区分独立跌倒、连续起身尝试、成功恢复和再次失稳。确认触发机制后，再测试支撑相位切换、稳定过渡和按姿态分类的起身流程；完成稳定性验证之后评估更快步态。

## 可开关的诊断操作

运动诊断默认关闭。`--diagnostics` 适用于 `--attack` 和 `--match`，仅增加传感器读取与记录，不修改导航阈值、动作文件、起身判定或速度。诊断文件每 40 ms 记录一次，另在实际接受动作切换时记录切换前后快照。

在仓库根目录、已激活 `robotics-tdp` 的终端执行：

```bash
python tests/run_webots_check.py --attack --visible --diagnostics --locomotion legacy --seed 27 --output runs/motion_debug_03
python tools/analyze_motion_diagnostics.py runs/motion_debug_03 --robot RedForwardA --output runs/motion_debug_03/motion-summary.json
python tools/evaluate_run.py runs/motion_debug_03 --output runs/motion_debug_03/metrics.json
```

已有目录不能覆盖；重复测试改成 `motion_debug_04`、`motion_debug_05`。测试成功时窗口自动退出；中途可在启动终端按 Ctrl+C，保留已写入日志。诊断开关增加日志体积和运行开销，正常比赛可去掉该参数。

`motion-RedForwardA-*.jsonl` 包含 IMU 弧度、`motion_time_ms`/`motion_duration_ms`、12 个腿部关节的目标/实测角与差值、`LFsr`/`RFsr` 的传感器局部坐标系三维力。原有球员与裁判日志继续保留。脚力未经支撑状态标定，不能直接将某个分量的正负解释为支撑脚。

分析报告的 `tilt_episodes` 将连续超过 0.8 rad 的采样合并为区间，并列出开始时的姿态、动作播放时间、前一切换和最大关节跟踪误差。连续起身尝试可能属于同一次物理跌倒；姿态暂时回到阈值内也可能拆成多个区间。需结合参考高度、脚力和画面判断，不能把区间数直接当成跌倒次数。

[Webots R2023b Motion 文档](https://github.com/cyberbotics/webots/blob/R2023b/docs/reference/motion.md)说明，`stop()` 保留播放位置，`play()` 可继续该位置；`isOver()` 表示最后目标已发送，并不保证关节已实际到位。因此诊断读取实际播放时间，而不只使用动作启动后的时长。[TouchSensor 文档](https://github.com/cyberbotics/webots/blob/R2023b/docs/reference/touchsensor.md)说明三维力使用传感器局部坐标系；当前模型两只脚的传感器均为 `force-3d`。

## 单项优化顺序与验收

1. 先复现固定种子的单人进攻，定位第一次倾角越界之前的切换；暂不扩大到四对四。
2. 在无球隔离夹具分别复测直行、侧移和动作衔接。现有 `--motions` 检查独立动作，尚不能代替衔接夹具。
3. 若失稳集中在切换，单独测试按实际播放相位和支撑状态选择过渡；若起身在侧倒或持续下落时启动，单独测试姿态分类与稳定着地等待。两项分开对照。
4. 每项候选至少复测三次相同初始条件，比较进球、用时、侧移时长、物理跌倒与恢复情况；固定种子重复主要证明可复现性，不证明普遍成功率。通过后再测试不同球位、朝向和种子。

回归标准：保持单人进球，减少失稳和反复恢复，整体用时不退化。横向滞回候选已因整体退化撤回；在失稳来源确认之前不继续扩大阈值或启用 Sprint。

## 实际诊断复测

`runs/motion_debug_02` 使用 `--attack --diagnostics --seed 27`，完成 3719 个时间步的运动采样，147.16 秒进球。进攻结果与原基线完全相同；动作次数、时长、球员轨迹和决策统计一致，球路径统计仅有约 4.4e-15 m 的浮点累加差异。该单场结果支持诊断记录没有改变此夹具的行为，不证明所有模式均等价。

- 47.04 s 开始直行时，缓存动作从 840 ms 播放位置继续；48.04 s 转右侧移前仍记录 840 ms。首段 0.96 s 保护不能保证按该动作的中立相位切换。
- 49.40 s 右侧移期间 roll 已约 16.5°；49.60 s 切换左侧移前已约 32.3°。失稳在反向切换之前已经发展，不能归因于反向切换这一时刻本身。
- 49.72 s roll=0.857 rad（约 49.1°），pitch=-0.00518 rad（约 -0.30°）。这是明显的侧倾；当前只按 pitch 符号选择 `recover_back`。该选择缺少侧倒分类，但尚未对照验证更换恢复方式是否成功。
- 倾角连续越界区间为 49.72–55.28 s；起身动作启动两次，不能计成两次独立跌倒。越界开始时最大腿部关节目标/实测误差约 0.0211 rad，来自 RHipRoll；单点误差不能解释整体重心失稳。

第一次诊断尝试 `motion_debug_01` 因脚力指针读取方式错误而崩溃，已中断，不能用作性能结果。已改为固定读取三个分量，并加入指针边界测试。修正后单元测试共 44 项通过，实际复测完成且无控制器崩溃。

匿名运行证据、数据窗口与图像见 [verification/motion-diagnostics](../verification/motion-diagnostics/README.md)。完整日志保留在本地忽略的 `runs/` 下。当前新增内容仅用于诊断，失稳与恢复问题尚未修复。

## 当前单人稳定模式

后续完整进攻的固定站姿过渡候选因退化未采纳；新的 guarded 调度则结合动作周期、重新起播、站姿收稳与双脚受力进行决策。标准初始条件的三次严格测试均无倾倒与恢复并完成进球。当前 `--attack` 默认采用 guarded 调度，复现本文历史失稳需显式指定 `--locomotion legacy`。方法、验收与范围见 [SINGLE_PLAYER_STABILITY.md](SINGLE_PLAYER_STABILITY.md)。
